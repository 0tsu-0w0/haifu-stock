# 改善メモ(まだ手を付けていないもの)

2026-10-09 時点。対応したら、この表から消すか「対応済み」に移す。
番号は [要件定義書](要件定義書.md) の機能番号。

## 使いにくそうなところ

### 1. iPhone のホーム画面のアプリと Safari でデータが別になる
- **困ること**: ログインのメールのリンクは Safari で開く。ホーム画面に追加したアプリで記録したデータは、Safari でログインしても引き継がれない
- **原因**: Supabase の標準のメール送信ではテンプレートを編集できず、6桁のコードをメールに入れられない。そのため、リンクでログインするしかない
- **対応案**:
  - Gmail のアプリパスワードを使って、Supabase に独自のメール送信(SMTP)を設定する。テンプレートに `{{ .Token }}` を入れれば、コードでログインできる。アプリ側の入力欄は作成済み
  - Google でのログインを有効にする。アプリ側は作成済みで、Google Cloud と Supabase の設定だけが残っている
- **必要な作業**: Supabase と Google の管理画面での設定(サークル主が行う)

### 2. 準備画面が長い
- **困ること**: 持ち込む品目、イベント価格、レジの並び順、釣り銭、経費、削除が、1画面に縦に並んでいる。目的の場所まで長くスクロールする
- **対応案**: 画面の上に「品目 / 並び順 / 釣り銭 / 経費」へ飛べるタブ(またはページ内リンク)を置く

### 3. 値引きがカートからしかできない
- **困ること**: 1部だけの値引きでも、カートを開いて品目を入れ、金額を入れる手順が要る
- **対応案**: 長押しのメニューに「値引きして記録」を足す。金額と理由をその場で入れられるようにする

### 4. 集計の切り替えと、持ち主の付け替え(要件の「必須」)
- **F-708**: レポートと分析を「全体(受託分を含む)/ 自分の分だけ / 持ち主別」で切り替える機能がまだない
- **F-709**: 品目の持ち主を、あとから付け替える機能がまだない。登録の誤りや、当日あとから預かった分の訂正に使う。付け替えたら、過去の集計と精算書を再計算する

## あると便利なもの(要件の「推奨」など)

### 5. 印刷所の価格表と、刷り部数のシミュレーション(F-106、F-108、F-1105)
- 「50部 18,000円 / 100部 24,000円」のような価格表を、品目ごとに登録する
- 需要予測の3案と組み合わせて、横軸を刷り部数、縦軸を予想利益にしたグラフを出す。利益が最大になる部数と、赤字になる範囲を示す
- データベースには `print_price_tiers` の表がすでにある。画面と計算がまだない

### 6. 価格を変えたときの試算(F-1106)
- 頒布価格をスライダーで動かすと、損益分岐部数がその場で変わる
- 需要は変えない単純な試算であることを画面に明記する

### 7. その他の推奨・任意の機能(要件定義書より)
| 番号 | 内容 |
|---|---|
| F-1104 | 当日の時刻を横軸にした損益分岐(黒字になった時刻) |
| F-1107 | 再版を「初版から通算」と「その版だけ」で見分ける |
| F-1108 | レジに、黒字化までの残り金額を小さく出す(オン・オフ可) |
| F-1109 | グラフを画像として保存する |
| F-306 | 価格の構成から、必要な釣り銭の目安を出す |
| F-411 | 休憩・離席の時間を記録し、集計の販売時間から除く |
| F-706 | よく一緒に買われる組み合わせ(セットを作る参考) |
| F-710 | 記録した端末(誰が売ったか)ごとの内訳 |

## 確かめが必要なもの(実機で)
- レジ画面で「画面は消えません」と出るか(開発用のブラウザでは確かめられなかった)
- バックアップの書き出しで、ファイルが端末に保存されるか(iPhone は保存先を選ぶ画面が出ることがある)
- ログインのメールの送り直しで、残り秒数が正しく減るか
- 別のタブでリンクからログインしたとき、元のタブもホームに進むか
